# Plan: 02-03 — Backend Demand RPC Procedures

**Goal:** Implement the backend logic for demand lifecycle management via the RPC gateway.

**Requirements:** DEMD-01, DEMD-02

**Context:**
- Uses Hono + Supabase Admin (for now, as seen in `identity.ts`).
- Integrated into `apps/api/src/rpc/router.ts`.

**Proposed Changes:**

1. **API Handlers:**
   - Create `apps/api/src/rpc/demands.ts`.
   - Implement handlers:
     - `demands.create`: Validate with `createDemandSchema`, insert into Supabase using PostGIS `ST_SetSRID(ST_MakePoint(lng, lat), 4326)`.
     - `demands.listMyDemands`: Fetch demands where `contractor_id` matches current user.
     - `demands.update`: Update fields if status is not `encerrada`.
     - `demands.close`: Quick status update to `encerrada`.
2. **Router Integration:**
   - Import `demandHandlers` in `apps/api/src/rpc/router.ts` and merge into the main router.

**Verification Plan:**

1. **API Smoke Tests:**
   - Use `vitest` to test the RPC endpoints.
   - Mock Supabase or use a test database if available.
   - Verify that `demands.create` returns the created demand.
   - Verify that `demands.listMyDemands` returns the user's demands.
   - Verify role-based checks (only contractors can create demands if we decide to enforce that role).

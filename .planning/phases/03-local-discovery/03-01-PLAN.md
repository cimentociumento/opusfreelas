# Plan: 03-01 — Profile Categories & Spatial Migration

## Goal
Update the database to support provider service categories and spatial location for discovery.

## Context
- Phase 3 requires searching providers by category and location.
- The `profiles` table currently only has basic flags.
- Providers need a `location` (geography) and `service_categories` (array of text).

## Proposed Changes

### 1. Database Migration
Create `supabase/migrations/20260428000001_profiles_discovery.sql`:
- Add `location` column of type `geography(POINT, 4326)` to `profiles`.
- Add `service_categories` column of type `text[]` to `profiles`.
- Create a GiST index on `profiles.location` for spatial queries.
- Create a GIN index on `profiles.service_categories` for array containment queries.
- Add an RPC function `search_providers` that uses `ST_DWithin` and category filtering.

### 2. SQL RPC: `search_providers`
```sql
CREATE OR REPLACE FUNCTION public.search_providers(
  user_lat float8,
  user_lng float8,
  search_category text,
  radius_km integer DEFAULT 50
)
RETURNS TABLE (
  clerk_user_id text,
  is_provider boolean,
  service_categories text[],
  distance_meters float8
)
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
BEGIN
  RETURN QUERY
  SELECT 
    p.clerk_user_id,
    p.is_provider,
    p.service_categories,
    ST_Distance(
      p.location,
      ST_SetSRID(ST_MakePoint(user_lng, user_lat), 4326)::geography
    ) as distance_meters
  FROM public.profiles p
  WHERE 
    p.is_provider = true
    AND (search_category = ANY(p.service_categories) OR search_category IS NULL)
    AND ST_DWithin(
      p.location,
      ST_SetSRID(ST_MakePoint(user_lng, user_lat), 4326)::geography,
      radius_km * 1000
    )
  ORDER BY distance_meters ASC;
END;
$$;
```
